# 검증 게이트 원칙 (Verification Gates)

> [incident-casebook.md](incident-casebook.md) 사례에서 도출한 운영 원칙. 오케스트레이터·서브에이전트 공통 적용.
> 핵심 전제: **에이전트 산출물은 검증 전까지 "주장"이다. 죽는 에이전트보다 자신 있게 틀리는 에이전트가 비싸다.**

## G1. 주장 → 문서 유입 게이트

- 조사·분석 문서의 핵심 주장(판정을 바꾸는 사실)은 **1회 독립 재현 후에만** 문서화. (사례 C2)
- 검증 가능한 형태로 기록: 파일 동일성은 diff 출력/sha256, 수치는 원시 파일 경로+추출 명령, 카운트는 집합 나열. "확인했음"만으로는 무효.
- 오판 1건 발견 시 같은 문서의 형제 주장 전수 재검토. (C2에서 retire 카운트 오기 추가 발견)
- 다층 위임에서 상류 문서를 소비할 때: 자기 결정을 좌우하는 주장만이라도 스팟 재검증.

## G2. 통계·판정 파이프라인 게이트

- **selfcheck에 개선/음성 케이스 필수** — happy-path만 검사하는 selfcheck는 버그 은폐 장치다. (C1: 양수 곡선만 검사해 부호 버그 은폐)
- 부호·단위 규약(higher=better 등)은 소비 코드가 저장 규약 정의를 임포트하거나 명시 대조. min/max 선택은 규약 근거를 주석으로.
- 최종 방어선 = **원시 데이터 스팟 대조**: 리포터 출력 N건을 손으로 원시 파일과 대조하고 나서 판정 확정. (C1 발각 경로)
- 다중 기준 게이트는 **전 기준을 개별 검증** 후 종합 판정 — 첫 통과 기준에서 멈추지 않는다. (HBM G4 사례: 평균 오차 PASS만 보고 진폭비 FAIL 누락할 뻔)
- 사전 등록 기준은 분모·분류·경계 케이스 처리까지 명시. 모호하면 실측 후 "사후 명확화" 논쟁 비용 발생. (Compiler_Thermal §1-2 → v4 재작업)

## G3. 판정·폐기 결정 게이트

- "동일/무효/폐기" 판정은 **차이가 나야 할 필드를 특정하고 그 필드를 직접 열람**한 후에만. 부분 열람(앞 N행)으로 전체 결론 금지. (C3)
- 폐기·재실행·비가역 결정 전 독립 포렌식 1회(mtime 타임라인, 설계 문서 대조).
- 설계상 불변인 축의 "변화 없음"은 정상 신호 — 설계 문서와 대조 없이 버그로 단정 금지. (C3의 .stk)

## G4. 진단 게이트 (오진 방지)

- 래퍼가 예외를 삼키는 환경(pyaedt 등)에선 **네이티브 오류 회수 계측을 가설 수립 전에** 추가. 계측 비용 < 빗나간 가설 1개. (C4: GetMessages 계측 후 진범 즉시 확정)
- 같은 커맨드의 과거 성공 이력이 있으면 "코드 버그"보다 "환경 변화" 가설 먼저 — 대조 재실행으로 판별. (C4: A-S0 재실행이 국지 가설 전부 반증)
- misleading 로그 문자열은 원장에 "오도 주의"로 명기 — 다음 세션 재오진 차단.
- 신호 판정(STOP·미발화)이 의심될 땐 룰 조건을 원시 신호값에 그대로 적용해 재현 — 판정 로직은 원본 cond를 임포트, 하드코딩 복제 금지. (P9-A Task 41 성공 사례: 판별 결과 "STOP은 버그가 아니라 기능"으로 불필요 재실측 회피)

## G5. 위임·통신 게이트

- **워커 상태의 진실은 보고가 아니라 디스크** — idle/무소식 시 git log·산출물 mtime부터 확인, 그 다음 마무리 지시. (C5, C6)
- 알림은 at-most-once 가정 — 원격 유일 사본이 존재하는 시간 창을 코드에서 제거(fetch 즉시 autosave).
- 위임 프롬프트에 완료 조건 4항(테스트 숫자·커밋 해시·산출물 경로·최종 보고) 명시. 미준수 시 회수 절차(디스크 검증→마무리 지시) 표준 적용.
- 과금 실측 앞에는 "판별 먼저" 배치: 기존 데이터로 판별 가능한 질문을 소진한 뒤에만 과금 게이트 진입. (P9-A: 판별이 재실측 대상을 0으로 만들어 A100 0시간 종결)

## G6. 기록 게이트 (종결된 계열의 유지 조건)

- 2층 기록: 코드 repo JOURNAL.md 원장(이벤트 즉시 append+커밋, ISO 8601+tz) / vault PROGRESS.md 요약(페이즈 완결 시). (C7 이후 표준)
- 태스크 단위 원자 커밋 — 테스트 통과 즉시 커밋, 세션 말미 일괄 금지.
- 세션 재개는 git log + JOURNAL tail이 정본 — 사용자 기억에 의존 금지.

## 미해결 과제

- **보고 강제 장치 부재**: 완료 조건을 프롬프트에 명시해도 무보고 idle이 반복(C6 × 2회/일). 현재는 회수 절차로 우회 — 하네스 수준 해결(완료 훅, 구조화 보고 강제) 탐색 필요.
- **G1의 자동화**: "주장 → 문서" 게이트는 관례일 뿐 강제 장치 없음. 문서 커밋 훅에서 증거 블록(diff/해시/경로) 존재 검사 같은 경량 린트 검토.
